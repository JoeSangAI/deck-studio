# Deck Studio 能力模型与四个 Gate

## 什么时候读取

客户或学员可见、跨两种以上生产类型、含真实品牌资产或媒体、三个以上页面家族、进入多轮逐页反馈，
或用户明确要求使用 PPT God 时，在正式生产前完整读取本文件。

## 架构与单一所有者

| 位置 | 唯一职责 |
|---|---|
| `SKILL.md` | 入口识别、职责分工、四个 Gate 串联、最低验收 |
| 本文件 | 能力模型、Gate 条件、视觉母系统和反馈失效范围 |
| `production-routing.md` | `project_snapshot`、三种生产类型、证据、资产与装配契约 |
| `workflows/` | 已有 PPT 精修的分析、设计、执行、验证和交付顺序 |
| `focusmedia-integration.md` | 分众知识、媒体标准、真实环境与专项验收 |
| `templates/`、`scripts/` | 可重复的确定性执行与硬检查 |

同一规则只进入一个详细所有者；其他位置只保留入口和链接。

## 八项能力

| 能力 | 必须留下的可核验结果 |
|---|---|
| 权威源管理 | PPT God 项目 ID、工作流版本和 revision |
| 叙事与内容锁定 | Gate 1 已批准的逐页标题、主张、顺序和讲述责任 |
| 视觉证据治理 | 每页视觉职责、候选、用户选择、两轮搜索或明确缺口 |
| 页面类型判断 | `image_integrated`、`hybrid`、`native_editable` 之一 |
| 视觉母系统 | 五个核心家族、必要的项目家族及获批代表样张 |
| 真实资产治理 | 资产来源、保真等级、用户锁、文件路径和处理方式；来源有 checksum 时一并核对 |
| 装配与修改保真 | 原生对象、图片底图、精确覆盖物和媒体关系按类型装配 |
| 观众验收 | 问题清零、整册总览、高风险页复核和正式导出预检 |

## PPT God 是制作期唯一状态源

PPT God 保存项目、页面、证据、家族、问题、Gate 和导出预检。Codex 的所有变更携带
`expected_revision`；revision 冲突时读取最新快照、合并仍有效的用户修改后再提交。Deck Studio 只读
`GET /projects/{id}/project-snapshot` 的结果，不创建旁路清单，不与 PPT God 双写。

## Gate 1：内容与页序 (`content_order`)

可以批准：

- 页面从 1 连续编号，章节与转场自然；
- 每页只有一个听众可理解的主张；
- 可见文案与讲稿、来源、排除项分离；
- 用户按章节确认内容和顺序。

停止条件：页面重复、主张冲突、标题仍是制作指令或用户不知道如何讲。退回受影响章节和相邻转场，
不推翻仍有效的内容。

## Gate 2：视觉证据与页面路线 (`visual_evidence_route`)

### 先定视觉职责

- `evidence`：承担事实、人物、产品、界面、数据、案例结果、媒体环境或前后对比。
- `expressive`：承担场景、隐喻、氛围和概念表达。
- `text_led`：承担章节、金句、过渡或纯文字表达。

### 再定生产类型

- `image_integrated`：视觉质量优先，核心文字与画面一体生成。
- `hybrid`：视觉底图一体生成，少量关键对象原生可编辑。
- `native_editable`：结构、数据、媒体或课堂操作本身必须编辑。

证据页必须选中经用户确认的素材。用户提供素材时直接锁定；第一轮查项目、用户资料和官方来源，第二轮
定向搜索或候选生成。两轮无合格结果时只暂停该页，记录搜索范围、缺口和需要用户做的单一动作，禁止
用次优素材凑数。Gate 2 采用异常优先 + 全套缩略图，用户可批量确认高置信相似页，高风险页逐页确认。

## Gate 3：页面家族与构造样张 (`family_prototypes`)

核心家族：封面、章节、金句、数据、内容。案例、流程、视频和互动先作为标签；形成约三页以上稳定
重复形式时才升级为项目家族。

每个实际使用家族确认一张视觉代表页。家族第一次出现 `hybrid` 或从零 `native_editable` 时，再确认
对应构造样张。代表页确认只批准其所属家族与构造方式，批量页必须继承获批样张。若原生构造两轮仍
达不到视觉标准，优先改为 `hybrid`；结构必须全原生时继续专项设计。

## Gate 4：整套终验与正式导出 (`final_review`)

可以批准：

- 缺页、重复、遗漏、比例变形、低清、媒体错误、家族漂移和路线错配已检查；
- 所有历史反馈已修正并重新验证；
- 图片一体页保持一个基底，混合页同时有底图和原生核心对象，原生页未被栅格化；
- 阻断问题已关闭，且 `verification_result.passed: true` 与 `correction_version` 已记录；
- 导出预检 revision 与项目 revision 相同，全部页装配成功。

草稿导出不需要四个 Gate 全部通过，但必须明确标识为草稿。正式导出任一页失败时整体失败，不插空白页、
不静默降级、不复用旧产物。

## 资产与保真

`fidelity` 是跨页面类型属性：

- `exact`：用户或项目指定的真实文件；保持原件，来源提供 checksum 时一并核对，用户锁后禁止替换。
- `reference`：用于生成或融合时约束人物、产品、设备、环境、批准页面或构图。
- `generated`：由模型生成且不冒充真实事实的视觉。

真实产品先行：该出现产品、Logo、批准创意、截图或真实设备时，继续使用确认过的真实资产。图片页可把
原件作为参考输入，但不得声称融合结果与原件像素完全一致。需要逐字节保真的小对象使用独立精确图层。
AI 画面可能被误认为真实案例、投放或结果时，观众页标注“示意图 / AI 生成”。

## 视觉系统

先定义全册共用的画布、字体层级、色彩、边距、页码、安全区、信息密度和图片处理；再允许案例通过品牌
色、题材、纹理或小装饰形成变体。统一的是视觉母系统，变化的是页面类型、构图骨架和阅读节奏。

## 反馈失效范围

| 反馈 | 默认失效范围 |
|---|---|
| 改字、单页素材或处理方式 | 当前页及 Gate 4 |
| 家族样式或样张变化 | 同家族页面及 Gate 4 |
| 章节逻辑或顺序变化 | 受影响章节、转场及下游 Gate |
| 用户提供更新母稿 | 新文件成为权威源，相关来源页及下游 Gate |
| 修改全册母系统 | 所有家族样张、派生页及 Gate 4 |

用户自由反馈进入 Codex；PPT God 保存原话、页码、影响范围、状态、修正预览和复验。只有复验通过才关闭。

## 最终观众验收

1. **听众**：单页主张清楚、顺序自然、远距离可读；
2. **证据**：真实素材、来源、用户选择和 AI 标识准确；
3. **视觉**：五个核心家族及项目家族共享母系统且版式有变化；
4. **播放**：视频和音频能播放，截图不冒充媒体；
5. **结构**：三种生产类型真实、原生页可编辑、精确素材和最终图片可核验。
