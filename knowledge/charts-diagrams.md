# 可编辑图表与示意图规则

## 核心原则

**图表只表达已有数据，不编造数据。** 默认使用 PowerPoint 原生可编辑图表，让用户后续能修改数据、标签和样式。

## 什么时候用

- PPT 中已有明确数字、指标、分组或时间序列，但原呈现粗糙
- 用户提供了结构化数据或确认过的 chart spec
- 页面类型是数据页、预算页、效果对比页、方案评分页
- 图表能减少文字解释，让趋势、对比或结构更清楚

## 什么时候不用

- 数据来源不清楚，需要猜测或补数
- 页面主要是照片、截图、客户案例或密集文字
- 图表会挤压原文案，导致字号低于可读下限
- 原 PPT 已有合格图表，只需要统一字体、颜色和间距

## 支持类型

| kind | PPT 图表 | 适用场景 |
|------|----------|----------|
| `line` | 折线图 | 时间趋势、连续变化 |
| `bar` | 横向条形图 | 长标签分类对比 |
| `column` | 纵向柱状图 | 少量分类或季度对比 |
| `pie` | 饼图 | 单组占比，分类不超过 5 个 |
| `radar` | 雷达图 | 多维能力评分、方案画像 |

雷达图使用 `XL_CHART_TYPE.RADAR_MARKERS`，基础图表优先使用 PPT 原生 chart，不默认渲染 PNG。

## Spec 格式

```json
{
  "charts": [
    {
      "slide": 3,
      "kind": "radar",
      "left": 6.8,
      "top": 1.4,
      "width": 5.2,
      "height": 4.2,
      "categories": ["覆盖", "效率", "成本", "转化", "记忆度"],
      "series": [
        {"name": "方案A", "values": [80, 72, 65, 76, 88]},
        {"name": "方案B", "values": [70, 85, 78, 68, 74]}
      ]
    }
  ]
}
```

坐标单位是英寸。`series.values` 必须和 `categories` 等长；`pie` 只能有一个 series。

## 生成命令

```bash
python3 templates/chart_builder.py input.pptx \
  --output output.pptx \
  --spec chart_spec.json \
  --primary "#C9A84C" \
  --secondary "#4A3F35"
```

## 设计规则

- 图表标题、单位和数据口径必须来自原文或用户确认
- 标签数量过多时，优先横向条形图或拆页，不强塞
- 雷达图维度通常控制在 4-7 个，系列通常控制在 2-3 条
- 饼图分类超过 5 个时，改为条形图
- 图表区域至少保留 0.15 英寸外边距，避免贴边
- 图表是信息层，不能被装饰线、插图或截图压住

## 失败信号

- spec 中出现未经确认的新指标或新数值
- 图例、标签、坐标轴互相压住
- 分类过多导致字小于 8pt
- 图表遮挡原文案、页码、logo 或关键图片
- 生成后 PPTX 无法打开，或图表退化成不可编辑图片

失败时先回到设计阶段，减少分类、拆页或改为表格；不要用装饰遮盖图表问题。
