# 阶段 2：设计（Design）

## 目标
基于分析结果，决定"改什么 / 不改什么 / 怎么改"。在动手前和用户对齐方案。

## 必做事项

### 2.1 确定改动优先级
按"严重度 × 修复成本"排：

| 严重度 | 修复成本 | 优先级 |
|--------|----------|--------|
| 高 | 低（删一行/调一个参数） | P0 |
| 高 | 高（要重画） | P1 |
| 中 | 低 | P1 |
| 中 | 高 | P2 |
| 低 | 任意 | P3 |

### 2.1.1 生成每页策略表

从 `audit.json` 读取场景和页面类型，形成策略表：

```text
P01 cover          sparse       策略：强化第一视觉，标题深色可读，logo 稳定
P02 overview       medium       策略：三栏/模块化，收敛字号层级
P03 timeline-plan  dense        策略：先保日期和预算可读，修压线
P04 timeline-plan  dense        策略：同 P03，保持方案间一致
P05 case-image     medium       策略：图片证据为主，统一图框
```

如果同一 deck 出现多个画像，以用户最终用途为主；无法判断时默认 `general-business`，用稳健商务风格。

### 2.1.2 建立页型家族和改造强度

在代表页制作前，把所有改动页归入以下四种强度之一：

| 强度 | 适用 | 允许改变 |
|---|---|---|
| `image-led` | 封面、目录、章节、转场、金句、封底 | 整页构图和视觉母题，保留冻结文案与真实资产 |
| `native-redesign` | 价值总览、流程、活动体系、场景总览 | 原生重排，但保留事实、文案、图片和逻辑 |
| `shell-unify` | 政策截图、设备结构、图墙、复杂案例 | 只改外层标题、背景、边距、页码和必要字体 |
| `preserve` | 本身已清楚或改动收益低的复杂页 | 仅修明确错误 |

为每个家族记录：页码、视觉锚点、标题规则、字体、背景、边距、图片处理、必须保持和验收方式。
代表页确认只批准其所属家族，不能自动外推到未覆盖页型。

当改动覆盖 3 页以上、涉及 2 个以上页型或准备批量应用规则时，把结果写入
`page_families.json`，批量执行前运行：

```bash
python3 templates/verify_page_families.py page_families.json
```

最低结构：

```json
{
  "slide_count": 36,
  "changed_slides": [2, 6, 10, 11],
  "families": [{
    "name": "image-chapters",
    "mode": "image-led",
    "slides": [2, 11],
    "representative": 2,
    "visual_contract": {
      "visual_motif": "同一场景摄影母题",
      "title_system": "同位置无衬线大标题"
    }
  }]
}
```

`shell-unify` 家族必须额外提供非空的 `must_preserve`，列出不可改变的截图、标签、图片主体和对应关系。
只改 1–2 页且不批量复用规则时，在设计稿中直接写明页型、视觉契约和保护边界，不额外创建 JSON。

### 2.1.3 承担主动审美诊断

当用户只能说“这页不好看”或“色块位置很怪”时，不要求用户继续替 Agent 做设计诊断。逐页回答：

1. 第一视觉是否明确，还是标题、色块、图片和数字同时抢注意力？
2. 图片之间是主图/证据、先后、对比还是并列关系？版式是否表达了这种关系？
3. 文字归属于哪张图或哪个模块？距离、对齐和颜色是否让归属清楚？
4. 色块是否承担分组、强调或导航？若没有，它是否应该删除？
5. 页面在同页型家族中是否像同一套稿，同时保留自身内容需要？

先修关系，再修装饰；先建立视觉重心，再决定是否增加图片、色块或卡片。

### 2.2 制定修复策略
对每个问题，方案要回答三个问题：

1. **根因是什么**？（不是症状）
2. **为什么会出现**？（避免复发）
3. **怎么改最小代价**？（能不删就不删，能不动就不动）
4. **如何验证不回归**？（截图、XML、文字保真、比例检查）

### 2.3 主动暴露取舍
有些问题有"改 vs 不改"的取舍，主动告知用户：

示例：
> "P3 的灰色装饰线有两种解法：
> A. 删除装饰线（最干净，但少了品牌感）
> B. 把装饰线从 y=5.5 上移到 y=4.5（保留视觉，但 P3 顶部已经满了）
> **我推荐 A**，因为删除对整体观感影响最小。"

### 2.4 输出设计稿
设计稿必须包含：

1. **改动清单**（每条对应一个根因）
2. **不改清单**（明确划界，避免"自由发挥"）
3. **执行顺序**（先改哪个，最后改哪个）
4. **风险点**（哪些改动可能引入新问题）
5. **验证清单**（每个关键页用什么证据验收）

## 产品/AI 背景设计规则

当用户给产品图、要求封面/封底/章节页更匹配产品时，先选设计路线：

| 路线 | 适用 | 禁止 |
|------|------|------|
| 高清氛围底图 + 产品主体叠加 | 用户图低清、但需要品牌氛围 | 把低清图放大到全屏 |
| 真实产品图局部保留 + AI 扩展场景 | 产品图可清晰裁切 | AI 生成伪产品文字/伪 logo |
| 纯抽象产品色底图 + PPT 文本层 | 产品图文字很多/容易失真 | 在背景图里生成正文 |

**强制约束**：
- AI 底图 prompt 明确：无文字、无 logo、无产品标签、无水印。
- 真实产品图必须等比缩放；低清图只可作为参考或局部主体，不可全屏铺底。
- 标题、口号、logo 必须保留为 PPT 可编辑图层，不能烘焙进底图。
- 封面/封底要留安全区：标题区与产品主体区分开，避免文字压包装。

详见 `knowledge/product-backgrounds.md`。

## 图片驱动封面与章节页

- 先重写标题：封面和章节标题应表达这一部分的核心判断，而不只是“市场分析”“案例参考”等栏目名。
- 页面不含必须保真的媒体、产品或人物时，标记 `ppt-god-full-image`，把已确认标题、正文和构图要求
  放入同一次 16:9 整页生成。页面含精确视觉资产时改为 `reference-fusion`，先锁定实际
  `reference_assets`，再由专业图片 Skill 或支持参考编辑的图片能力完成整页；PPT God 项目使用
  `import-slide-image` 接回已验收页面。
- 页面涉及分众知识、原页或媒体时，完整读取 `references/focusmedia-integration.md`，按其中的资产链、
  页面契约和专业验收设计；普通页面不增加分众字段。
- 同一 deck 的封面与章节页使用一个视觉母题，通过隐喻变化区分章节，不逐页换一套画风。
- 逐页检查文字准确性、换行、字重和层级；只有实际出现问题时才对该页做定向修改或重出。
- Logo、二维码和法务标识不能交给图片模型生成。提示词必须为真实资产预留安静安全区；装配时按
  `logo-only` 或 `precision-assets` 清单后贴并做碰撞检测。屏幕创意在专业带框阶段锁定，环境中的
  整台媒体设备和主构图进入参考融合。
- 代表页先生成并检查，再批量生成其余章节页，避免五张“各自好看但互不相干”的图。

## 关键决策点

### 决策 1：删 vs 改
- 元素是冗余的（装饰线、遮罩、重复文本）→ **删**
- 元素承载了信息（图片、图表、核心文本）→ **改**

### 决策 2：精确 vs 可读
- 容器宽度足够（> 1.5"）→ 精确算法（按天/按像素定位）
- 容器偏窄（< 1.0"）→ 粗粒度算法（按周）+ 换行文本

### 决策 3：加辅助 vs 减装饰
- 当前元素多 → 减装饰
- 当前元素少 → 可考虑加辅助（但保持克制）
- 原模板已有页眉线/短强调线/分隔线 → **复用或标准化原元素**，不要叠加同角色装饰线
- 顶部 1 英寸内已有图片墙、截图、活动照片 → 禁止新增页眉线穿过图片；必要时把分隔线放在图片下方

### 决策 4：生成背景 vs 修原图
- 原图低清、被拉伸会糊 → 生成高清无字底图 + 叠加真实产品主体
- 原图高清且产品本身重要 → 裁切/抠图/等比放置，不重绘产品文字
- AI 生成出现伪字/伪标 → 废弃，不修补；重新生成无字背景

### 决策 5：预览通过 vs 真实 PPT 通过
- 预览通过但用户截图仍异常 → 检查 PPTX XML / PowerPoint 实际截图
- 文本颜色在渲染预览中正确但 PowerPoint 发白 → 做窄范围样式兜底并复验
- logo 在预览中正确但 PowerPoint 红叉 → 替换为 PNG/JPEG，不用 SVG/bin

### 决策 6：统一标题 vs 保留原标题结构
- 顶区只有一个可见标题 → 可统一字体/颜色，但不要无脑改坐标
- 顶区有多个宽文本框（占位标题 + 模板标题）→ 先用原稿截图判断谁实际可见；隐藏文本只保留 XML，不参与视觉
- 若原稿中某个标题是白色/透明/被模板遮住 → 不要批量染成深色，否则会产生标题冲突

### 决策 7：批量重染 vs 跳过文本层
- 普通文字页 → 可统一标题/正文颜色
- 截图拼贴页、电脑屏幕页、社媒案例页、复杂叠图页 → 默认跳过内部文字重染，只处理外层标题/页眉
- 如果某页依赖黑字在白色截图上、白字在深色遮罩上同时出现，批量按“深页/浅页”重染会造成信息丢失，必须逐文本框确认

### 决策 8：小插图 vs 保持留白
- 稀疏概念页、章节页、方法论页缺视觉锚点 → 可用白底/纯色底小插图，抠图后作为独立 PNG 图层
- 页面已有产品图、客户截图、活动照片、数据图表 → 默认不加插图，先优化已有证据
- 页面密集或正文偏多 → 保持留白和分组，不新增插图
- 插图 prompt 必须无文字、无 logo、无水印；GPT Image 2 不请求透明底

### 决策 9：可编辑图表 vs 图片图表
- 基础折线、柱状、条形、饼图、雷达图 → 优先 `templates/chart_builder.py` 生成 PPT 原生可编辑图表
- 数据来源不明确、需要推断、需要补数 → 不生成图表，先让用户确认数据
- 分类过多、标签过长 → 改用横向条形图、拆页或保留表格
- 视觉效果不能压过可读性；图表标签和图例必须先能读清

## 反面示例（禁止）

- ❌ 不出方案直接动手（"先改改看"）
- ❌ 方案里没有"不改清单"（"自由发挥"会导致回归）
- ❌ 不暴露取舍（让用户在 A/B/C 里盲选）
- ❌ 原模板已有页眉线，还再叠一条页眉线
- ❌ 把原本隐藏的占位标题统一染成可见深色
- ❌ 对复杂截图页按整页明暗批量重染所有文本
- ❌ 为了“好看”给密集页强加插图
- ❌ 没有明确数据就生成折线图、雷达图或评分图
- ❌ 把可编辑图表默认导成不可改的 PNG
- ❌ 样张通过后把同一布局机械覆盖到未验证的复杂页型
- ❌ 用户说“不好看但讲不清”时停止判断，等待用户逐项指定位置和字号
- ❌ 用没有分组、强调或导航功能的色块填补空白
