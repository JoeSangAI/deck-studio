# 阶段 1：分析（Analyze）

## 目标
拿到 PPT 后，先不急着动手。把"页面在讲什么 / 哪里有问题 / 改动的优先级"摸清楚。

## 必做事项

### 1.1 扫描基本信息
- 页面数量、尺寸（16:9 / 4:3）
- 每页的 shape 数量、图片数量、文本框数量
- 提取主标题文字、字体、字号
- 提取主流配色（HEX 值）
- 提取每页可见文本清单，用作后续保真校验基线
- 提取图片资源类型和尺寸：PNG/JPEG/SVG/bin、像素尺寸、宽高比
- 标记可能在 PowerPoint 里失效的资源：SVG、`.bin`、外链图片、异常 content-type

**保真基线**：用户要求"文字/图片不能变"时，必须先保存三份清单：
1. `source-text.json`：每页可见文字
2. `source-media.json`：每页图片数量、尺寸、类型
3. `source-preview/`：原稿每页截图

**通用审计命令**：

```bash
python3 templates/deck_audit.py input.pptx --out audit.json
```

`audit.json` 里的 `scenario_guess` 和每页 `archetype_guess` 必须进入 design 阶段；不要审计完又凭主观套模板。

### 1.2 先看轻量总览，再细看关键页

先把全册渲染到磁盘，并生成一张轻量 WebP contact sheet。主上下文只查看这张总览一次，用它完成页面
分型、异常页识别和风格锚点选择。然后只细看：

- 本次涉及页型的 2–3 张风格锚点；
- contact sheet 中被标记为异常或高风险的页面；
- 用户明确指出的页面。

单页细看前降采样到约 1280–1500px；不要查看原尺寸全册总览，也不要把所有页面逐张读入上下文。

**工具**：
```bash
soffice --headless --convert-to pdf input.pptx
pdftoppm -r 150 input.pdf preview -png
python3 scripts/contact_sheet.py preview \
  --out source-contact.webp --cols 5 --width 320
```

### 1.3 识别问题类型
对照 `knowledge/check-list.md` 的全部问题类型，标记出当前 PPT 存在的问题：

| 问题 | 严重度 | 涉及页 |
|------|--------|--------|
| 装饰线压图 | 高 | P5-P8 |
| 图片压字 | 高 | P8 |
| 文字溢出 | 中 | P2 |
| 日期与月份轴对不齐 | 中 | P3-P4 |
| PPT 实际打开与预览不一致 | 高 | P1/P9 |
| 低清产品图被硬拉成背景 | 高 | P1/P9 |
| ... | ... | ... |

### 1.4 输出分析报告

汇报模板：
```
已分析完这份 PPT：
- 页数：X 页，尺寸 16:9
- 主题基调：[商务正式/快消/...]
- 页面类型分布：内容密集 N 张，图文混排 M 张，纯文字 K 张
- 现有问题（按严重度排序）：
  1. [高] P5-P8 装饰线压图
  2. [高] P8 图片压字
  3. [中] P2 文字溢出
  4. ...
- 配色现状：主色 #XX，辅色 #XX
- 字体现状：标题用 XXX，正文用 XXX
- 风险资源：SVG/bin 图片 X 个，低清位图 X 个，可能失效 logo X 个
- 保真基线：已记录 / 未记录（未记录不能进入 execute）
```

## 特别警报

出现以下任一情况，必须先停下来做根因判断：

- 用户截图里出现红叉/图片占位符 → 优先查 SVG/bin/外链图片，而不是重画页面
- 渲染预览和 PowerPoint 打开效果不一致 → 优先查 PPTX XML 样式和应用兼容
- 用户给的是低清产品图 → 不能直接全屏放大当背景，走 `knowledge/product-backgrounds.md`
- 时间轴上方/边缘有标签压线 → 查文本框 bbox，不要只凭肉眼移动

## 反面示例（禁止）

- ❌ 不看页面就动手（"先改改看"）
- ❌ 看完一遍就报问题（不写文档，过两天就忘）
- ❌ 只看封面和尾页（中间内容页才是问题高发区）
