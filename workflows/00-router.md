# 阶段 0：路由（Router）

## 目标

用户只给一个 PPT 时，不要先问风格。先把 PPT 自动分型，决定修复深度、视觉方向、页面策略和验证门槛。

## 默认输入策略

如果用户只说“帮我优化/美化/精修这个 PPT”，默认：

- **内容保真**：不改原文案，不删除原图，不改事实/数字
- **保守重排**：先做版式、层级、对齐、可读性、风格统一
- **可编辑输出**：文字仍是 PPT 文本层，图片仍是图片层
- **不问问题**：除非文件打不开、缺关键素材、或用户要求需要外部信息

## 0.1 先跑自动审计

```bash
python3 templates/deck_audit.py input.pptx --out audit.json
```

`templates/analyze_ppt.py` 只保留为旧命令兼容别名，内部仍调用同一个 `deck_audit.py`，不要重复运行。

审计至少得到：
- 页数、尺寸、页面密度
- 每页标题/文本量/图片量
- 字体和颜色分布
- 高风险媒体资源
- 页面类型初判

## 0.2 判断任务模式

| 模式 | 触发条件 | 策略 |
|------|----------|------|
| `conservative-polish` | 默认；用户强调内容/图片不变 | 保留内容，优化版式和风格 |
| `visual-redesign` | 用户要求“重新排版/精美/大改” | 保文案和图，重构页面布局 |
| `brand-background` | 用户给产品图/KV/品牌图 | 生成/重构封面章节底图 |
| `illustration-needed` | 稀疏页缺少视觉锚点，且没有真实图片证据 | 生成白底/纯色底小插图，抠图后作为可移动图层 |
| `data-chart` | 已有明确数据、评分、时间序列或方案对比 | 用 PPT 原生可编辑图表重画 |
| `dense-cleanup` | 大量文字/表格/时间轴 | 优先可读性和信息分组 |
| `template-follow` | 用户给模板/参考风格 | 继承模板，不自由发挥 |

没有明确要求时，优先 `conservative-polish`，避免过度设计。

## 0.3 判断场景画像

按 `knowledge/scenario-profiles.md` 选一个主画像：

- 客户提案/销售方案
- 内部经营汇报
- 产品/品牌发布
- 投资人/数据报告
- 培训/课程材料
- 政企/正式汇报
- 作品集/案例展示
- 密集附录/资料包

画像只决定**视觉语气和证明物优先级**，不能改内容事实。

## 0.4 判断页面类型

每页按 `knowledge/page-archetypes.md` 归类：

- 封面/封底
- 章节页
- 目录/总览
- 策略总览
- 时间轴/路线图
- 方案罗列/对比
- 数据/表格
- 图表/示意图
- 图片案例/活动现场
- 人物/IP/背书
- 密集文字页

不同类型用不同修法，不要全套同一模板。

## 0.5 输出路由结果

在动手前形成一段内部 plan：

```text
模式：conservative-polish
主场景：客户提案/销售方案
页面类型：
- P1 封面：重做视觉层级，保产品图比例
- P2 策略总览：卡片层级收敛
- P3-P4 时间轴：优先修压线和标签可读
- P5-P8 图片案例：统一图框和标题层级
- P9 封底：高清底图 + 深色文字
- 稀疏概念页：仅在不挤压正文时使用小插图资产
- 数据页：仅用已确认数据生成可编辑图表
验证门槛：文本保留、图片比例、PPTX 兼容、contact sheet
```

## 失败信号

- 还没看全册就直接开始做封面
- 所有页面套同一种卡片模板
- 密集页做成营销海报，导致信息看不清
- 数据不清楚时生成新图表或补数字
- 页面已有真实证明物时再添加抢主体的小插图
- 图片页为了统一而裁掉关键主体
- 用户只给 PPT，却要求用户补一堆风格信息
